# NINMODS — Project Rules & Engineering Standards (`docs/RULES.md`)

> **বাধ্যতামূলক নীতি (Mandatory Directive):** এই প্রোজেক্টে কাজ করার পূর্বে যেকোনো এআই এজেন্ট (AI Agent) বা ডেভেলপারকে এই ডকুমেন্টের প্রতিটি ধারা শতভাগ অনুসরণ করতে হবে। কোনো কাজের শুরুতে সম্পূর্ণ কোডবেস এন্ড-টু-এন্ড রিভিউ করতে হবে এবং বাস্তব ও পরীক্ষিত প্রমাণ ছাড়া কোনো কাজ সম্পন্ন ঘোষণা করা সম্পূর্ণ নিষিদ্ধ।

## ১. স্ট্যান্ডার্ড জাভাডক / ডক্সিজেন কমেন্টিং নীতি (Javadoc / Doxygen Style Comments ONLY)

* **ব্যানার ও ডেকোরেটিভ কমেন্ট সম্পূর্ণ নিষিদ্ধ (Zero ASCII Banners):**
  কোডের ভেতর বা ডকুমেন্টে কোনো প্রকার ব্যানার লাইন যেমন:
  ```cpp
  // =========================================================================
  // State Query Helpers
  // =========================================================================
  // -------------------------------------------------------------------------
  // ═════════════════════════════════════════════════════════════════════════
  /* ####################################################################### */
  ```
  লেখা সম্পূর্ণ নিষিদ্ধ।

* **স্ট্যান্ডার্ড ডকুমেন্টেশন স্টাইল (Official Javadoc / Doxygen Format):**
  প্রতিটি মেথড, ফাংশন, কনস্ট্রাক্টর, স্ট্রাক্ট এবং ক্লাসের পূর্বে অফিসিয়াল ডক্সিজেন (C/C++) বা জাভাডক (Java/Kotlin) ফরম্যাটে কমেন্ট লিখতে হবে:
  ```cpp
  /**
   * @brief Reads the current health points of a player entity.
   * @param p Virtual memory address of the player entity in target memory.
   * @return Current HP value, or 0 if unresolvable.
   */
  static int readHP(uint64_t p) {
      // Implementation
  }
  ```
  - অবশ্যই `@param` দিয়ে প্রতিটি প্যারামিটারের উদ্দেশ্য ব্যাখ্যা করতে হবে।
  - অবশ্যই `@return` দিয়ে রিটার্ন ভ্যালুর ধরন ও তাৎপর্য ব্যাখ্যা করতে হবে।
  - এক্সেপশন বা এরর হ্যান্ডলিং থাকলে `@throws` বা এরর কোড উল্লেখ করতে হবে।

## ২. প্যাকেজ ডিক্লারেশন ও ইমপোর্ট হেডার বাধ্যতামূলক অডিট নীতি (Mandatory Package & Import Header Audit)

* **কাজে হাত দেওয়ার আগে ও পরে অডিট:**
  যেকোনো ফাইলে কাজ করার সময় বা কোড এডিট করার পূর্বে ও পরে ফাইলের শুরুতে থাকা প্যাকেজ ডিক্লারেশন এবং প্রতিটি ইনক্লুড/ইমপোর্ট স্টেটমেন্ট লাইন-বাই-লাইন পুঙ্খানুপুঙ্খভাবে মিলিয়ে দেখতে হবে।
* **অনুপস্থিত বা ব্রোকেন হেডার প্রতিরোধ:**
  কোনো হেডার বাদ পড়া বা ভুল পাথের কারণে যেন কম্পাইলেশন এরর (যেমন `fatal error: file not found` বা `cannot find symbol`) তৈরি না হয়।
* **অকেজো বা ডুপ্লিকেট ইমপোর্ট পরিহার:**
  কোনো ডুপ্লিকেট বা অব্যবহৃত ইনক্লুড ফাইলে রাখা যাবে না।

## ৩. সম্পূর্ণ কোডবেস এন্ড-টু-এন্ড রিভিউ নীতি (Mandatory Full Codebase Audit)

* **কাজে হাত দেওয়ার আগে সম্পূর্ণ কোড রিভিউ:**
  - যেকোনো পরিবর্তনের পূর্বে সম্পূর্ণ সংশ্লিষ্ট কোডবেস ম্যানুয়ালি রিভিউ করতে হবে।
  - বিচ্ছিন্ন একটি ফাইল বা ফাংশন পরিবর্তন করে কাজ শেষ দাবি করা সম্পূর্ণ নিষিদ্ধ।
* **সম্পূর্ণ পাইপলাইনের ইন্টারকানেকশন ম্যাপিং (Trace the complete execution path):**
  `Linux / Android Init (main.cpp)` ➔ `Native Window Creator (ANativeWindowCreator.h)` ➔ `Raw Touch Polling (Touch.cpp)` ➔ `ImGui Frame Render (draw.cpp)` ➔ `UI Menu & Bar (menu.cpp, bar.cpp)` ➔ `ESP Dispatch (func/esp.hpp)` ➔ `Game Data Memory Engine (game/data.cpp, Offsets.h)` ➔ `Kernel / Syscall Memory Read (memory.hpp)`
  এই সম্পূর্ণ ট্রানজিশন চেইনের প্রতিটি স্তর যাচাই করতে হবে যাতে কোনো এক স্তরের পরিবর্তন অন্য কোনো স্তরে ব্রেক না ঘটায়।

## ৪. মাস্টার সুইচ ও ১০০% ম্যানুয়াল মেনু কন্ট্রোল নীতি (Master ESP & 100% Manual Menu Gating)

* **সবকিছু ডিফল্টভাবে বন্ধ থাকবে (Default to OFF):**
  সবগুলো ফিচার (`cfg::esp::enabled`, `box`, `name`, `health`, `armor`, `distance`, `weapon`, `bot_tag`, `skeleton`, `tracer`, `crosshair`, `firing_ind`, `loot`, `AimSilentEnabled`) ডিফল্টভাবে `false` থাকবে।
* **জিরো অটোমেটিক বিহেভিয়ার (Zero Automatic Behavior):**
  মেনু থেকে ব্যবহারকারী নিজে অন না করা পর্যন্ত কোনো মেমরি রিডিং, অফসেট স্ক্যানিং বা রেন্ডারিং চালু হবে না।
* **ইনস্ট্যান্ট পজ ও মেমরি সেভিং (Instant Memory Pause):**
  মেনু থেকে মাস্টার সুইচ বন্ধ করা মাত্রই ডেটা ইঞ্জিন এবং রেন্ডারিং লুপ সাথে সাথে বন্ধ হবে (`if (!cfg::esp::enabled) return;`)। এর ফলে লবিতে অপ্রয়োজনীয় CPU/মেমরি ব্যবহার ও অ্যান্টি-চিট ডিটেকশন ঝুঁকি সম্পূর্ণ দূর হবে।
* **ইউজার স্টেট প্রিজারভেশন (Sub-Feature State Preservation):**
  মাস্টার সুইচ বন্ধ করলে সাব-ফিচারগুলোর সিলেক্টেড স্টেট (যেমন Box, Distance, Skeleton) রিসেট হবে না। পরবর্তীতে মাস্টার সুইচ চালু করলেই পূর্বের সিলেক্টেড ফিচারগুলো পুনরায় সক্রিয় হবে।

## ৫. স্ট্যান্ডঅ্যালোন নেটিভ আর্কিটেকচার নীতি (Standalone Native Overlay Client)

* `refer/ZqwClient` হলো একটি স্ট্যান্ডঅ্যালোন নেটিভ অ্যান্ড্রয়েড এক্সিকিউটেবল (`client.sh-arm64`)। এটি সরাসরি SurfaceFlinger নেটিভ উইন্ডো তৈরি করে এবং রুট প্রিভিলেজ নিয়ে মেমরি রিডিং (`process_vm_readv`) পরিচালনা করে।
* `refer/refer/app` হলো রেফারেন্স ইউনিটি IL2CPP হুক প্রোজেক্ট (`PrabirxLive.cpp`, `MAFIA.h`, `KittyMemory`)। মেকানিজম বা অফসেট মিলিয়ে দেখার জন্য এই রেফারেন্স প্রজেক্ট অনুসরণ করতে হবে, কিন্তু মূল ক্লায়েন্টের স্বচ্ছতা অক্ষুণ্ণ রাখতে হবে।

## ৮. রেসপন্স ফরম্যাট নীতি (Mandatory Final Response Headings)

প্রতিটি কাজের চূড়ান্ত রিপোর্টে বাধ্যতামূলকভাবে নিম্নলিখিত ৫টি সেকশনে প্রমাণভিত্তিক তথ্য উপস্থাপন করতে হবে:
1. **Implemented** — কী কী পরিবর্তন করা হয়েছে এবং কীভাবে তা রিকোয়ারমেন্ট পূরণ করেছে।
2. **Files reviewed/changed** — রিভিউ করা ফাইল এবং পরিবর্তিত ফাইলের স্পষ্ট তালিকা।
3. **Verification evidence** — প্রকৃতপক্ষে রান করা কমান্ড এবং তার ফলাফল।
4. **Issues found/fixed** — চিহ্নিত সমস্যা ও তার সমাধান।
5. **Not verified / remaining issues** — সীমাবদ্ধতা বা অবশিষ্ট থাকলে তা সুনির্দিষ্টভাবে উল্লেখ করা।
